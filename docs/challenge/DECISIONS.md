# Decisions (plain-language summary)

Source of record: `.orch/DECISIONS.md` (internal log). This page explains each decision for people who were not in the room.

## Ground-truth differences from the spec's audit (SPEC section 1)
- The repo already contained untracked files `facetime/annotate_video.py`, `facetime/call_render.py`, `facetime/heatmap_intro.py`; they were left alone (D-01).
- `src/rtcoach/pose.py` tracked only one person; the judge needs two to detect "two people" (D-09).
- The rep counter registers a rep when the person is 15% back up from the bottom, so the finishing lockout is not yet visible at that moment (D-10).
- No fixed depth, knee or hip-line gate existed; the strict judge adds them (see D-15 to D-20). Since 2026-10-13 the live judge is the lenient j3 and the liveness test is off (D-34).
- Chert's command line had no messaging surface, so iMessage behaviour was first behind flags (D-07). Since then the Chert Messaging API was built and iMessage works live.
- The audit said "no per-caller identity". Still true today: Chert exposes only a hashed caller id (no phone or email), so attribution uses the claim window (D-06). Chert said on 2026-10-13 that it will pass the caller's handle, with no date (D-35).

| D-34 | OWNER DECISION 2026-10-13: the liveness "cheater test" is OFF and the judge is the lenient j3. `liveness_enabled` is false in the live `judge_thresholds`; the code and tests stay, and one config change turns it back on. | D-37 | We will not use outbound FaceTime for competition calls. Any use is limited to an optional "you're up" voice nudge alongside the text | No video means no judge, so Brodie ringing people is not a way to run calls and not a way around B1 |
| D-38 | OWNER REQUEST 2026-10-13: team members get no daily call cap. This reuses the existing "team / test account" flag (`clients.is_team`, already audited and already a button on the admin users page) rather than adding a second flag, so that one mark now means both "leave me out of the growth metrics" and "no daily cap". It exempts them from nothing else: their calls are still counted, still score and still appear on the public leaderboard, and the honest call count is kept, so the fair key (fewest calls today first) still means what it says. Queue priority was deliberately NOT part of this decision; the owner asked for it the same day and it is D-43. Known cosmetic gap: an iMessage to a team member over the cap still reads "0 calls left today"; the website says "No cap" | The team needs to test the live line without burning out at 5 calls, and there was no per-user cap override at all - the alternatives were raising the cap for everyone or an unaudited row edit that the call-end path recomputes anyway. Anyone already marked as a tester is someone we already decided is not a competitor |
| D-40 | Alert texts: the dispatcher's 10-minute dedupe key now includes the message, not just the kind, and each host check sends its own kind. Before this, every check in `infra/monitor.py` texted under the single kind `infra`, so whichever one ran first silenced every other host problem for the whole window (on 2026-10-13 a stale heartbeat row hid both the Chert agent being down and the missing token expiry). The "token expiry unknown" reminder is now one text a day instead of one every ten minutes, and texting `LIFE` (or `HEALTH`) from a number in `team_alert_handles` asks for a health report on demand - verdict, live alert conditions, line state, worker heartbeat, queue length, failed texts, window. Team-only: anyone else gets the ordinary unknown reply | The owner's alert thread was both too loud and too quiet at once: the same nag every ten minutes, while real problems in the same window were dropped. A report on demand replaces guessing from whichever alert came through, and a per-message key means a new problem always gets its own text |
| D-41 | OWNER REQUEST 2026-10-13: display names may contain single internal spaces, so `JOIN stan lee` registers "stan lee". 3-20 characters of letters, numbers and underscores in space-separated words: no leading, trailing or doubled space, no tabs, and runs of whitespace are collapsed before the check. One rule in one place (`ch_valid_display_name`), shared by the text join, the web join, the clients CHECK, the parser and the site's form | People type their name the way they say it, and "JOIN stan lee" used to come back as a name error. Every existing name is the same rule with one word, so nothing is rewritten and `lower(display_name)` uniqueness is unchanged |
| D-42 | OWNER REQUEST 2026-10-13: the team gets a live view of the line. Two texts per call to `team_alert_handles` only - "LIVE: <name> is on the line now" when a line picks up, "Line free again: <name> was on for 3m" when it hangs up - with the number waiting in both. The watcher is a jobs step that compares each line against what it last saw (stored in `ch_job_state`), so a dispatcher restart re-announces nothing, and `team_line_alerts` turns it off live without a deploy | The owner wanted to see the line being used as it happens. Reusing the alert handles and the outbox means no new delivery path and no risk to competitors; keeping the last-seen state in the database (not in memory) means a restart mid-call does not text twice |
| D-43 | OWNER REQUEST 2026-10-13: team members are popped first. The same one flag (`clients.is_team`, audited `ch_admin_set_team`, one click on the admin users page) now means three things: out of the growth metrics, no daily cap (D-38), and the front of the line. Pop order is `priority desc, calls_today asc, entered_at asc, id asc`, so a team member goes ahead of every non-team member however long the others have waited, team members stay fair among themselves, and nothing changes for anyone else. Applied at pop time only: a connected call or a live claim is never taken away, so a team member waits for the current call to end. Positions stay truthful - a waiting contestant's place really does move back when a team member joins, on the site and in the admin queue view | Testing the live line means getting on it now, not after the queue drains, and D-38 alone did not help when someone was already waiting. The honest count is still untouched, so the leaderboard and the cap keep reading the same numbers; one flag keeps 'this is us, not a competitor' in one place |
| D-44 | OWNER REQUEST 2026-10-13: an admin score adjustment moves valid reps too. `score_adjustments` gained a `reps` column and `ch_admin_adjust` a `p_reps` argument; leaving it blank (which is what every existing caller does) mirrors the points delta onto the rep count, and typing an explicit delta - including 0 - decouples them for a points-only correction. `ch_valid_reps` and `ch_user_stats.valid_reps` are now judged reps + Σ adjustments.reps, floored at 0, so the leaderboard card, the profile, the texted stats and the board's VALID REPS tile all move together. Existing adjustment rows were backfilled with reps = points, which is what fixed the standings that already read 45 pts next to 52 reps. Per-day and per-call reporting (`user_daily_public`, admin metrics) deliberately stays judged-reps-only | One valid rep is one point in this competition, so a correction that moved only the points made the public board contradict itself, and there was no way at all to fix a rep count that the judge got wrong |
| D-45 | OWNER REQUEST 2026-10-13: push-ups are judged from a phone in front of the person, not only side-on. Counting already worked from every front angle; the fault was the opposite one - from a raised front phone, perspective shrinks the shoulder's travel in the image, so the shoulder-drop depth signal read "deep" and half reps were accepted (5 of 6 at a straight front view propped 35 deg up, all of them at 50). The depth elbow is now read from the world landmarks when the image angle is foreshortened, and a straight arm (10 deg past the depth limit) can no longer be passed by the shoulder drop. Judge version j5; nothing else about the gates moved, so a deep rep is accepted exactly where it was before | The owner wanted to set the phone in front of them and have it work. Supporting a view honestly means both halves: real reps count from there (they already did) and fake ones do not (they did). The world elbow is a 3-D angle - 82 deg on every deep rep and 142 on every half rep, at every camera angle tested - so it is the one depth signal that does not care where the phone is |
| D-46 | OWNER REQUEST 2026-10-13: be more lenient for a phone in FRONT of the lifter, which is how most people will film. Measured first: a 100 deg push-up filmed front-on from floor level was rejected EVERY time (0 of 45 accepted) while the same rep side-on passed always, because a lens in front of the lifter distorts the image elbow BOTH ways - an arm pointing at it reads bent when straight (D-45) and reads straight when bent, which is what called good reps too_shallow. Depth now uses the 3-D world elbow when the image saw no bend at all (>= 150 deg), so honest 70-118 deg reps are accepted from a front phone exactly as often as side-on (45 of 45 at flat, 35 and 50 deg props). Half reps are still rejected everywhere | Leniency has to be aimed at the real cause or it just lowers the bar. The image elbow was the broken measurement, not the threshold, so nothing was loosened: the depth limit, the drop limit and every other gate are untouched, and the real-footage ship gate still accepts the same clean and off-angle reps and still rejects every cheat. The world angle is only trusted where it cannot invent a rep - a visible bend in the image still wins, because trusting world depth generally accepted a real knee push-up |
| D-47 | OWNER REQUEST 2026-10-14: two cash prizes instead of one. The top scorer still wins `first_prize`, and a new `drawing_prize` of the same size goes to one entrant drawn at random, where **one valid rep is one ticket**. This reverses D-22, but not the design D-22 cancelled: the old raffle needed 100 valid reps to enter, this one weights the draw by every rep, so there is no threshold to clear and no cliff. Power hour deliberately does NOT double tickets - it still doubles points - so the drawing cannot be farmed by stacking one hour. The draw is `challenge.scoring.draw_winner`: entrants sorted by public id, tickets laid out as consecutive ranges, winner picked with SHA-256 of a recorded seed, so the same seed and entrants always reproduce the same winner and a dispute is answerable. The same person can win both prizes. Official Rules lost the "there is no raffle" term and gained the drawing, its odds basis and a no-purchase-necessary line; rules copy says "random drawing", not "raffle", because raffles are separately regulated in most US states while a no-entry-fee drawing is not | Winner-take-all had a dead-weight problem: once someone posts a big number every rep by everyone else is worth nothing, so people stop calling. Linear tickets make every rep worth the same wherever it lands, which keeps a casual caller in it without taking the leaderboard away from the top scorer - a 500-rep caller still holds 50x the tickets of a 10-rep one. Applied during the test run, so no announcement and no retroactive unfairness to settle |

## Decisions you may be asked to make
- Run the j3 real-clip check before the public push, or accept launching without it? See `BLOCKERS.md` B4.
- Turn on `HANGUP_MODE=chert_api` after one test call? See `BLOCKERS.md` B6.
- Turn liveness back on (D-34)? Only by a config change plus a fresh look at the parked branch.
- Which accounts are team members (D-38, D-43)? Anyone already marked team/test is now uncapped AND popped first - check the admin users page, since B3 says tester rows are still in the database.
- Should a team member be hidden from the public leaderboard (D-38, D-43)? With no cap and the front of the line they can out-score the field, and `is_team` does not unlist them today. Separate change, not done.
- Have Brodie ask for the queue code on the call (D-36)? Cheap insurance against a stranger burning someone's turn while caller ID is still missing.
- Add an outbound "you're up" voice nudge (D-37)? Audio only, and it means standing up our own LiveKit room; the text already covers it.
