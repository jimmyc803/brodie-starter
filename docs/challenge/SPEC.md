# Brodie Push-Up Challenge — Build Spec (source of truth)

Verbatim-in-substance copy of the team's build prompt. Every task file refers to sections here as §N.
Reliability and cheat-resistance matter more than speed. Ship in phases.

## 0. Mission
Public 7-day push-up competition on Brodie (AI fitness coach on FaceTime + iMessage via the Chert SDK).
- Users FaceTime Brodie's number. A strict AI judge counts valid push-ups only. Points go to a live leaderboard website.
- Users text Brodie commands over iMessage: join, queue, status, leaderboard.
- One shared FaceTime line, one call at a time → a priority queue decides who calls next.
- Context: virality push for IvyHacks: Beat Muse (Penn). Demo of "Brodie for Coaches" (per-rep form data → coach dashboards + muscle heat map). The Brodie avatar on the leaderboard is the heat map turned into a game.
- Failure modes: a judge that lets cheaters through (kneeling, half reps, replayed video); a judge that rejects legit reps. Judge is the most important component.
- Window: launch Mon Oct 12 2026 → Sun Oct 18 2026 23:59:59 America/New_York. Day boundaries = midnight ET. tz-aware datetimes everywhere; test midnight rollover.

## 1. Ground truth (prior audit; verify; record diffs in DECISIONS)
Rep counting: RepCounter2.update() src/rtcoach/repcount2.py (~l330); built in facetime/pipeline.py (~l36); facetime/perception.py turns counted reps into rep events. Push-ups track 5 signals (MASK ~l68): both elbow angles, elbow angle 3D, shoulder height, shoulder height 3D, wrist height; rest→down→up; rep counts when 2 of best 3 agree. Elbow signal = sum of elbow angles /90. Start threshold 0.3 first rep then 60% of own avg rep size. Count lands at 15% back from bottom (40% first rep). Min 0.8s between reps. Torso must be ~horizontal. No fixed depth/form gate (relative to own average; only filter drops reps <50% usual size). Fault classifier labels (`pushups - shallow`, `pushups - insufficient`, `pushups - elevated hips`) never block counting; accuracy unvalidated. Rep event fires live; reps saved to DB with faults[] only at call end. Reconnect within --leave-grace-s (2s) continues count; a new FaceTime = new room/session. Known accuracy: front-propped phone over-reads ~2 at bad floor angle; shallow reps undercounted; 87% exact on MM-Fit, 59% vs coaches on home sessions.
Data: Supabase Postgres project `beat-muse`, service role via facetime/supa.py; local JSON per call under data/tmp/sessions/. Tables coaches, clients, programs, program_days, assignments, sessions, sets, reps (faults[]), muscle_scores. No per-caller identity: all calls under DEMO_CLIENT_ID; only identifier is Chert call_id. chert_call metadata at call start is printed but never read and may contain caller handle. Timestamps: sessions.started_at/ended_at, same on sets, time offset per rep.
Calls: one Chert line, one dispatch name AGENT_NAME. Chert handles second FaceTime during active call. After each call line offline a few minutes; incoming calls ring out; our code can't see busy. --max-s 300 (worker.py ~l545) only makes the coach leave; unverified whether Chert hangs up. SessionSink.finish() (facetime/session_sink.py) writes sets/reps/end time, only when DEMO_CLIENT_ID set.
Messaging: no iMessage code in repo. Brodie's number once sent an unprompted text from Chert-side systems.
Persona/cues: starter/persona.md only with --voice gemini; coaches.persona from DB; hooks in starter/handlers.py. say_now can only use pre-recorded phrases → add to cues.json and re-render audio.
Recording: no video/audio stored. Promise: "a log of rep counts and cues, not the video or the audio." NEVER store user video or audio.
Runtime: env LIVEKIT_URL, LIVEKIT_API_KEY, LIVEKIT_API_SECRET, AGENT_NAME, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, GEMINI_API_KEY, DEMO_CLIENT_ID in .env.local. Run: `python -m facetime.worker dev` and `chert dev --agent`; `chert login` may be needed. Team runs coach code + owns Supabase; Chert runs the line (busy, hangups, iMessage transport). Worker hosted on AWS (Chert approved).

## 2. Product rules (locked; every number in `competition_config`, editable live, never hardcoded)
Scoring: points = valid reps × multiplier (1×, 2× in power hour). Cumulative across the window. Rank by points; tiebreak = who reached the tied total first. Show valid reps and points separately. Only valid reps score; rejected reps shown with reasons, score 0.
Calls: total 3:15. 0:00–3:00 counting window (setup inside it). 3:00–3:15 reveal (counting stops). Then agent ends call. Max 5 counted calls per person per ET day. A call counts toward cap if attributed and lasted ≥30s OR produced ≥1 rep. Gatekeeper-rejected calls never count. No cooldown.
Queue: next = fewest counted calls today (tiers 0–4), ties FIFO by queue entry. Never interrupts a call. Can't be queued while on a call. Users at cap can't queue (tell reset time). Claim window 90s: "you're up, FaceTime now"; no-show removed, told to text QUEUE again, next gets slot. Walk-ins: line idle AND queue empty → any eligible user can call; dispatcher claims line on connect. Gatekeeping: caller isn't current claim holder → pre-recorded "not your turn" cue, leave within ~5s (covers unregistered, at cap, someone else holds claim). Doesn't count, no reps recorded.
Power hour: one per ET day, random start 12:00–22:00 ET, never same hour two days in a row. Valid reps 2× if the rep timestamp is inside the hour (per rep). Announce in morning recap, 15 min before, at start. Respect quiet hours.
Engagement: rank-drop texts ("You dropped from #4 to #7. #6 is 12 points ahead.") on drop ≥2 places, throttle 1/user/3h, none in quiet hours. Streaks = consecutive ET days with ≥1 counted call having ≥1 valid rep; badge on leaderboard + STATUS. Daily recap 10:00 ET to opted-in users: yesterday's points, total, rank, streak, today's power hour, site link. Daily TikTok shoutout manual: admin shows yesterday's top scorer + best single call.
Avatar: original cartoon athlete designed from scratch (resemble no existing character/brand). Chest, triceps, front delts, core visibly grow across ~10 levels as points stack (only those). Level thresholds in config. Appears on leaderboard (small), profile (large), post-call result card, in-call reveal if video supported.
Prizes (display only): 1st $100; top 3 group call with a UFC fighter; raffle for everyone ≥100 valid reps (reps not points), prize TBD in config. Raffle draw script reproducible + auditable: seeded from a value published before the draw, result logged.
Eligibility: 18+, US, iPhone. One person one account. JOIN confirms 18+ and rules. Alt accounts give no advantage (reps stay with account) — note in rules.
End: at Sun Oct 18 2026 23:59:59 ET freeze scoring; reps after freeze don't count; leaderboard "FINAL — pending verification". Top 3 do a live verification call before payout. Admins can void calls / adjust scores; every adjustment has a reason, written to audit log.

## 4. Architecture
iPhone FaceTime → Chert line(s) → EC2 facetime.worker (strict judge: gates + classifier veto + liveness; caller resolution + gatekeeping via dispatcher; 3:00 cap, 3:00–3:15 reveal, end call; call events → dispatcher; reps → Supabase at end).
iMessage ↔ Chert iMessage API ↔ EC2 dispatcher (FastAPI): inbound commands webhook; line state machine + priority scheduler; throttled outbound queue (quiet hours); jobs: daily recap, power hour, rank-drop, freeze; result-card renderer (PNG).
Browser → website (Next.js on Vercel) ← Supabase (source of truth, realtime).
Boundaries: Supabase single source of truth; no process-only state that matters. Only the dispatcher changes line_state and queue, each change in a transaction with SELECT … FOR UPDATE. Worker never decides eligibility: `POST /calls/start {call_id, line_id, handle?}` → `{decision: accept|reject, user_id?, reason, cue}`. Worker reports lifecycle with idempotency keys: call_started, call_ended, reps_committed. Website public read-only via views + RLS; admin area requires authenticated team accounts on email allowlist.
Call sequence: 1 call connects, worker gets chert_call. 2 worker → /calls/start. 3 dispatcher resolves user (handle or claim window), checks eligibility, line claimed (or idle for walk-in) → in_call, returns decision. 4 reject: cue, leave, record nothing. 5 accept: judge runs; at 3:00 counting stops, reveal till 3:15; agent leaves/ends call. 6 worker commits session/sets/reps (per-rep metrics + validity) via SessionSink keyed to real user_id; keeps local JSON. 7 worker sends call_ended; line → offline_until = now + LINE_OFFLINE_GAP_S. 8 dispatcher recomputes points, leaderboard, rank deltas; sends post-call card and rank-drop texts. 9 when offline_until passes line → idle; scheduler pops next user, claimed(user, expires_at=now+90s), texts "you're up".
Failure: worker crash mid-call → on restart recover unsent sessions from data/tmp/sessions/, commit idempotently by call_id; dispatcher times out in_call after max call length + 60s. Dispatcher restart: state in Postgres, jobs resume, duplicate webhooks deduped by message id. Supabase write failure: retry with backoff, keep local JSON, reconciler every minute commits uncommitted local sessions.

## 6. Strict judge (most important)
Principle: valid only if passes every deterministic geometric gate. Fault classifier is a second veto (can reject, never approve). RepCounter2 decides that a rep happened; gates decide whether it counts.
Setup: side view, full body. Guide: phone on floor/low surface ~6–8 ft to the side, landscape, head to feet visible, good light. Counter is tuned for front-propped phone → recalibrate for side view; if side view breaks the 5-signal counter (bilateral elbow average with one arm hidden), adapt: visible-side elbow + shoulder-height + wrist signals. Document every change.
Gates (starting values in judge_thresholds; tune with harness):
| Frame | shoulders, hips, knees, ankles (visible side) conf ≥ min_conf for ≥90% of rep frames | not_in_frame |
| One person | exactly 1 person for the rep | multiple_people |
| Knees | knee angle ≥160° whole rep AND knee never within knee_floor_margin of floor line (floor line from ankle+wrist keypoints during plank) | knees_down |
| Plank line | shoulder–hip–ankle deviation ≤15°; sag and pike both fail | hips_sag / hips_pike |
| Depth | elbow ≤90° at bottom AND shoulder drops to within depth_margin of elbow height | too_shallow |
| Lockout | elbow ≥160° at top before next rep | no_lockout |
| Tempo | duration ≥0.8s; flag implausible sustained cadence | too_fast |
| Torso | existing horizontal-torso check | not_horizontal |
| Classifier veto | pushups - shallow / insufficient / elevated hips, or any knee or sag label | classifier:<label> |
Liveness (anti-replay): once per call at random time 0:45–2:30, challenge cue random from "Tap your left shoulder" / "Tap your right shoulder" / "Lift your right hand"; 4s to perform, verified by pose. Pass → continue. Fail → one retry with a different challenge; fail again → void the call's reps (liveness_result=fail) and cue why. Reps during challenge window don't count and aren't penalized.
Live feedback cues (add to cues.json, re-render audio): "Knees up — that one didn't count." "Go lower — chest down." "Lock out at the top." "Get your whole body in frame — side view." "Keep your hips in line." "One person in frame only." three challenges + "Challenge passed" + "Challenge failed — reps voided." "Not your turn — text QUEUE to Brodie to get in line." "You've hit today's limit — come back tomorrow." "You're not signed up yet — text JOIN and your name to Brodie." "Thirty seconds left." "Time!" "Check your texts for your results." "Power hour — every rep counts double." Rate-limit corrective cues; most important reason wins.
Versioning: judge_version on every rep. scripts/rejudge.py recomputes valid/reject_reasons/points from stored metrics under new thresholds; dry run with diff report + apply mode with audit log entry.
Harness: judge_eval/ labeled clips (team-recorded, local, consent, testing only, NEVER uploaded, gitignored). judge_eval/labels.yaml per clip: expected valid count, expected rejected by reason, camera setup. Categories: clean (several people/body types), knee, half reps, hip sag, pike, no lockout, fast sloppy, partially out of frame, two people, phone filming a laptop playing push-up video (replay), bad lighting, slightly off-angle. `python -m judge_eval.run` replays through the same code path as live; per-clip + aggregate metrics.
SHIP GATE: 0 accepted reps across cheat clips (knees, half, sag, pike, no lockout, replay, two people); ≥90% clean reps accepted; per-clip count error ≤1 on clean; realtime latency on actual EC2 type keeps up with stream fps with headroom (report p50/p95). If not passable with clips available, report which categories need more footage.

## 7. Queue scheduler + line state machine
States: idle → claimed(user, claimed_until) → in_call(user, call_id) → offline(offline_until) → idle. All transitions in one Postgres txn with row locks.
idle→claimed: scheduler pops. idle→in_call: walk-in (queue empty, eligible caller connects). claimed→in_call: claim holder connects (any connect in claim-window mode). claimed→idle: claim expired → queue entry no_show, text user, pop next immediately. in_call→offline: call_ended or timeout at max length + 60s. offline→idle: offline_until passes, then pop.
Pop order: calls_today asc, entered_at asc; skip at cap, banned, opted out, in a call. Multi-line: pop for each idle line.
ETA: (position−1) × rolling avg cycle (avg connected duration + offline gap) + remaining time on current call/offline; show ranges ("~10–15 min").
Property tests: nobody with fewer calls today waits behind someone with more; FIFO within tier; no user holds two active entries; a no-show never blocks the line longer than claim_window_s. LEAVE or opt-out leaves immediately. Freeze at window_end: stop popping, close queue; a call in progress at freeze scores only reps timestamped before window_end.

## 8. Messaging (iMessage via Chert adapter)
MessagingProvider interface: send_text, send_image, parse_inbound. ChertProvider, MockProvider (console + DB), WebOnlyProvider (no-op sends). Inbound webhook with signature verification if supported; dedupe by provider message id.
Commands (case-insensitive, tolerant, typo-friendly): JOIN <name> → validate, reply rules summary + "Reply YES to confirm you're 18+, in the US, and agree to the rules."; on YES register + link handle. QUEUE/Q/LINE → enter queue, reply position, ETA, calls left today; if idle and nobody waiting "Line's open — FaceTime now." STATUS/S/ME → points, valid reps, rank, calls left, streak, queue position, today's power hour. TOP/LEADERBOARD/LB → top 5 + site link. LEAVE. RULES → short + link. POWER. HELP. STOP → opt out of all proactive texts + leave queue, always honored; START re-enables. Unknown → short help (no LLM).
Templates (Brodie voice, hype coach, swearing toggle in config, never insulting): welcome, you're up (FaceTime now, 90s), missed slot, queue position update (only if improves ≥3 or ETA changes a lot), post-call result (card or link), rank drop, streak at risk (20:00 ET if no call today and streak ≥2), power hour announce / 15-min warning / start, daily recap, competition ending soon (Sunday 20:00 ET), final results.
Quiet hours 23:00–09:00 ET: no proactive texts; allowed: command replies, "you're up", post-call results. All outbound via throttled send queue (OUTBOUND_RATE_PER_MIN) with retries. Dedupe by (user, template, logical event).
Result card: server-rendered PNG 1080×1350 (Satori+resvg or Playwright). Avatar (before→after level), "+N points", valid vs rejected with reason breakdown, total points + rank change ("#9 → #6"), streak, next power hour, site URL. Bold gym aesthetic: dark bg, one loud accent, big numbers. Also /r/<call_id> with OG meta.
